# Contributing

Thank you for helping improve this project by Varun Madala.

## Development workflow

1. Create a focused branch from `main`.
2. Make one logically related change.
3. Run `python -m unittest -v` locally.
4. Update documentation when behavior changes.
5. Open a pull request describing the problem, solution, and validation performed.

## Quality expectations

- Keep domain logic small, readable, and testable.
- Add or update automated tests for behavioral changes.
- Do not commit credentials, secrets, proprietary information, PHI, or real personal data.
- Use synthetic fixtures for healthcare and member examples.
- Preserve backward compatibility or document intentional breaking changes.

## Pull request checklist

- [ ] Tests pass locally
- [ ] New behavior is covered by tests
- [ ] Documentation is current
- [ ] No secrets or sensitive data are included
- [ ] The change is focused and clearly explained

## Reporting issues

Include reproduction steps, expected behavior, actual behavior, and relevant environment details. Security-sensitive reports should not include exploitable details in a public issue.
